# Methods (Phase 1)

## Title (working)

Performance Evaluation of Qwen2.5-7B Across Self-Hosted, ECS, and Amazon Bedrock Deployments

## Goal

Evaluate the same instruction-tuned LLM under three deployment environments while holding model identity, decoding parameters, prompt construction, and API shape fixed.

## Deployments

| ID | Environment | Serving | Capacity unit |
| --- | --- | --- | --- |
| A | Self-hosted lab | vLLM, CUDA 13.x, Ubuntu 24.04 | 1× RTX 3090 (24 GB), no TP, single GPU |
| B | AWS ECS | vLLM on `g5.xlarge` | 1× NVIDIA A10G |
| C | Amazon Bedrock | Custom Model Import | 1+ imported model copies (see ModelCopy) |

This is a **capacity-fair** comparison (one replica / one GPU-class unit each at baseline), not a claim that GPUs are identical. Cost and throttling are first-class metrics for that reason.

## Fixed factors

- Model: Qwen2.5-7B-Instruct
- Temperature 0, top-p 1.0
- OpenAI-compatible `POST /v1/chat/completions` with streaming (TTFT)
- LLMPerf workloads with input/output token stddev = 0
- Shared experiment configs under `configs/experiments/`

## Experiments

1. **Concurrency:** {1, 2, 4, 8, 16, 32, 64}
2. **Prompt length:** {512, 1024, 2048, 4096} tokens (8192 deferred until all backends allow longer context)
3. **Output length:** {128, 256, 512, 1024} tokens
4. **RAG TopK:** deferred to a later phase

## Metrics

- Latency: TTFT and end-to-end — P50 / P95 / P99
- Throughput: requests/s, output tokens/s
- Reliability: error rate, timeouts
- Resources (A/B): GPU util/memory/(power), CPU, RAM
- Bedrock ops metrics (recommended): CloudWatch `ModelCopy`, InvocationLatency, InvocationThrottles, token counts via `scripts/fetch_bedrock_metrics.py`

### Cost (triple reporting)

Do **not** treat each short LLMPerf cell as an independent 5-minute Bedrock invoice. Report:

| Field | Meaning |
| --- | --- |
| `normalized_compute_cost_usd` | `cost_per_hour × duration/3600` — **primary** efficiency metric |
| `standalone_billed_cost_usd` | Cell alone (Bedrock ≥1×5-min window) — cold/bursty analysis |
| `session_allocated_cost_usd` | Share of matrix **wall-clock** session bill (by requests; see `session_costs.csv`) |
| `cost_per_request_normalized_usd` / `cost_per_request_billed_usd` | Per-request views |
| `model_copies_observed` / `model_copy_source` | `cloudwatch` or `configured_assumption` |

**Self-host:** electricity-only (`$0.0525/hr`) **and** amortized TCO (`system_purchase_usd / lifetime_hours` + electricity ≈ `$0.1476/hr`). Primary uses amortized when `primary_hourly: amortized`.

**ECS:** GPU instance compute only (g5.xlarge). Phase 1 excludes EBS/ALB/NAT/transfer.

**Bedrock Custom Model Import:** CMU active-copy time in 5-minute windows, **not** per token. Prefer measured `ModelCopy` over `configured_assumption`.

## Limitations

- Short cells (<5 min) make per-cell Bedrock floors dominate; prefer normalized + session-allocated costs, and consider longer steady-state runs (10–15 min per concurrency level) for Phase 1.5.
- Self-host amortized TCO is a proxy (purchase + electricity), not full datacenter cost.
- ECS ancillary AWS services are omitted in Phase 1.
